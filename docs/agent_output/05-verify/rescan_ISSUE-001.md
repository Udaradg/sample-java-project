## 2. Reasoning

The root cause named three reaching paths for the unbounded findAll() mechanism: EmployeeSchedulerController.getAllEmployees(), EmployeeReportController.exportToExcel(), and WomenDaySchedulerImpl.printWomenDayMessage(). The patched source closes the first two at the database-query level: EmployeeSchedulerServiceImpl.getEmployees(Pageable) now calls employeeSchedulerRepository.findAll(pageable), and the controller clamps size to [1,100] and floors page at 0 (Math.min(Math.max(size,1),100), Math.max(page,0)) so no caller input can widen the read. EmployeeReportServiceImpl.writeExcelFile() replaced the single findAll()+full-list join+fully-buffered XSSFWorkbook with a do/while loop over employeeReportRepository.findAll(PageRequest.of(pageNumber++, 500)) writing each page's rows to a streaming SXSSFWorkbook(100) and disposing it, so no single in-memory structure ever holds the complete employee set, salary list, or workbook bytes at once; PAGE_SIZE is a hardcoded constant, not caller-controlled. Both changes push the bound into the query itself, exactly what the catalog's canonical_approach requires, and the catalog anti-pattern 'adding a page-size parameter the server does not cap' does not apply here. The third path, however, was only partially addressed: WomenDaySchedulerImpl.printWomenDayMessage() no longer calls the old getAllEmployees()+Java-side filter, but its replacement, employeeSchedulerService.getEmployeesByGender(GenderType.FEMALE) -> EmployeeSchedulerRepository.findByGender(gender), is a Spring Data derived-query method returning List<Employee> with no Pageable, cursor, or @QueryHints streaming -- it still materializes every matching document into memory in a single unbounded read, just scoped to one gender instead of the whole collection. That is a smaller working set for a typical roughly-even gender split, but the underlying mechanism -- an unthrottled full-result-set read triggered by a scheduled job -- is unchanged, and the CWE-770 catalog entry names this exact scenario as a known anti-pattern to avoid: 'Fixing the endpoint but leaving an equivalent unbounded call reachable from a scheduled job.' As the organization's female headcount grows, this job can still exhaust memory by the same mechanism the issue reported, just later.
