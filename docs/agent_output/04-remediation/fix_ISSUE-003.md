# Fix — ISSUE-003

## MongoDB (NoSQL) injection in the employee search endpoint via string-concatenated BasicQuery

## 3. Why this is the smallest correct diff

Apply the CWE-943 canonical_approach directly at the sink the root cause names: replace EmployeeSearchRepository.searchEmployees's StringBuilder-assembled BasicQuery with Spring Data's Criteria/Query API. Bind department with Criteria.where("department").is(department) so it can never be interpreted as query structure, and keep the name search substring-based but wrap the caller's value in Pattern.quote(...) inside the regex Criteria so it is matched as literal text, not caller-controlled regex or operator syntax. This changes the query-construction mechanism itself - the actual root cause - rather than trying to filter or escape specific characters out of the input, which the catalog identifies as insufficient. Complementary controller-side validation narrows what ever reaches the repository, but the repository-level rewrite is what removes the injection primitive.

**Catalog pattern (`CWE-943`):** Improper Neutralization of Special Elements in Data Query Logic (NoSQL/SQL Injection)
