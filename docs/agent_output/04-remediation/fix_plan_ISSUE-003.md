## 1. Remediation approach

Apply the CWE-943 catalog pattern by replacing the StringBuilder-built BasicQuery with Spring Data Criteria and Query construction. Bind department as an equality value, and where name search remains substring-based, use Pattern.quote on the supplied name so it is treated as literal text rather than caller-controlled regex syntax. This changes the query-construction sink itself, preventing input from becoming MongoDB operators or document structure instead of attempting to blacklist particular payload characters.

**Catalog pattern (`CWE-943`):** Improper Neutralization of Special Elements in Data Query Logic (NoSQL/SQL Injection)

## 2. Alternatives considered

- Escaping or blacklisting quotes, braces, and dollar signs - rejected because the CWE-943 catalog identifies character filtering as insufficient compared with parameterized criteria.
- Adding only a length limit or rate limit - rejected because it may bound abuse volume but leaves string-built query structure injectable.
- Keeping BasicQuery and wrapping construction in exception handling - rejected because it leaves the tainted string at the query sink.

## 4. Risks to watch

- Pattern.quote changes name input from caller-supplied regular expression syntax to literal text; clients that intentionally relied on regex semantics will need an explicit separate, safely designed search capability.
- Validation annotations may require an existing Bean Validation dependency or an approved adjacent configuration change, which must be recorded if the live module does not already provide it.
- ISSUE-002 leaves the endpoint unauthenticated until its separate plan is approved and implemented.

## 5. How the fix must be verified

1. Compile employee-service after replacing the query construction and adding any validated request handling required by the existing dependency set.
2. Replay a benign search such as name=Ann and confirm matching employees are still returned under the intended literal substring semantics.
3. Replay the documented name and department injection payloads and verify they are treated as literal values, returning no broad result set and never executing injected operators.
4. Verify overly long or malformed search parameters are rejected at the controller boundary, while the repository query still uses Criteria regardless of validation outcome.
5. Inspect employee-service logs for the search path and confirm constructed query text and raw request values are not logged.
