# Build Gate — Step 2

Phase C step 2, second half: **10_build-gatekeeper** runs `mvn verify` for every fix Fixer drafted a
diff for (Compiled or Compile Failed alike — this gate compiles the module itself, independently of
Fixer's own separate check) inside an isolated `git worktree`, and diffs the dependency tree before
and after the patch. This is the one report in the whole pipeline with **no agent-authored content
at all** — every line comes straight from the gate script, by design (deterministic CI/CD execution,
not open-ended agentic reasoning).

## Known caveat

This machine's only JDK is newer than this project targets, and its Lombok version does not process
annotations reliably on it — a `Failed` report whose errors sit outside the fix's own changed files
(e.g. a missing Lombok-generated `log` field or getter) is very likely this pre-existing toolchain
mismatch, not the patch. Cross-check the error locations against the fix's file list before treating
a build failure as the patch's fault.
