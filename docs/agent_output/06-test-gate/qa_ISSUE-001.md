## 1. What the new test proves

Proves the CWE-770 fix at GET /api/v1/employee: the controller must never let a caller obtain an unbounded read of the employee collection. Replays an adversarial request for size=999999 through EmployeeSchedulerController.getEmployees(page, size) and captures, via an ArgumentCaptor<Pageable>, the exact Pageable the controller hands to EmployeeSchedulerService.getEmployees(Pageable) -- asserting its page size is clamped to 100 (the server-enforced maximum) regardless of what the caller asked for. Before this fix the endpoint took no size parameter at all and always called the unbounded schedulerService.getAllEmployees()/repository.findAll(); this test targets the exact replacement seam (the Pageable construction) that removes that unbounded read. A second, benign case replays an in-bounds request (page=2, size=20) and asserts the Pageable is passed through unchanged, proving normal callers are unaffected.

**Mocking strategy:** EmployeeSchedulerService is Mockito-mocked (Mockito.mock(EmployeeSchedulerService.class)) and injected into a plain `new EmployeeSchedulerController()` instance via ReflectionTestUtils.setField, since the field is @Autowired-only with no setter/constructor and this sandbox has no embedded-MongoDB/Testcontainers dependency to run a live-repository test. The test never reaches MongoTemplate or a repository at all -- it asserts purely on the Pageable the controller constructs and hands downstream, which is exactly where the CWE-770 fix's server-side clamp (Math.min(Math.max(size, 1), 100)) lives.
