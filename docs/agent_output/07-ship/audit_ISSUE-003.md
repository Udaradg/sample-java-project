# Audit Trail — ISSUE-003

## MongoDB (NoSQL) injection in the employee search endpoint via string-concatenated BasicQuery

> ⛔ Blocked — not safe to ship.

_Written by the scribe agent on 2026-08-17, independent of outcome — this file exists whether the patch cleared or was blocked._

## Chain of custody

ISSUE-003 was registered as a Critical CWE-943 (NoSQL injection) finding in the issue register (`docs/agent_output/00-issues/issue-register.xlsx`): the employee-search endpoint built a MongoDB filter by concatenating raw `name`/`department` request parameters into a JSON string and executing it with `BasicQuery`, letting a caller supply operator syntax (`$ne`, `$where`, etc.) that changed the query's structure rather than just its values. Root-cause analysis (`docs/agent_output/02-root-cause/root_cause_ISSUE-003.md`) traced the taint from `EmployeeController.searchEmployees` through `EmployeeServiceImpl.searchEmployees` to the string-built `BasicQuery` in `EmployeeSearchRepository.searchEmployees` (High confidence), and blast-radius analysis (`docs/agent_output/03-blast-radius/blast_radius_ISSUE-003.md`) scoped the exposure to the one search endpoint plus a degraded `report-service` export path, rated P0/Critical. The fix strategist's plan (`docs/agent_output/04-remediation/fix_plan_ISSUE-003.md`, Status: Approved) called for replacing the StringBuilder/BasicQuery construction with Spring Data's Criteria/Query API (binding `department` and wrapping `name` in `Pattern.quote(...)`), plus complementary controller-side allowlist validation, and flagged as an open risk that the allowed-character set for that validation still needed to be decided. The Fixer drafted and compiled the smallest diff matching that plan (`docs/agent_output/04-remediation/fix_ISSUE-003.md`, `fix_ISSUE-003.diff`, Status: Compiled). All three Step 1 verification checks then ran in isolated worktrees: re-scan found the vulnerable signatures (`BasicQuery`, `StringBuilder`, string-built filter/log) entirely gone and the planned `Criteria`/`Pattern.quote` construction in their place — verdict FIXED, High confidence (`docs/agent_output/05-verify/rescan_ISSUE-003.md`); red-team attempted operator-injection, regex/ReDoS, `Pattern.quote`-escape, field-name-injection, allowlist-bypass and type-confusion vectors against the patched code and found none of them reopened the injection primitive — verdict NO_BYPASS_FOUND, Medium confidence (`docs/agent_output/05-verify/redteam_ISSUE-003.md`); but behavior-guard compared the diff against the plan's stated scope and found it BEHAVIOR_CHANGED at High confidence (`docs/agent_output/05-verify/behavior_ISSUE-003.md`): beyond the planned query rewrite and allowlist, the diff silently drops the repository's `log.info(filter)` and the controller's `log.trace(name, department)` calls with no mention in the plan, an empty `?department=` parameter that previously matched everything now returns HTTP 400 instead of being treated as no-filter, and previously-accepted characters (e.g. `R&D`, underscores) in name/department are now rejected — none of which the plan's own general risk note about 'an explicit permitted-character set decision' concretely specified. The QA gate then drafted one new regression test replaying the issue's documented injection payload against `EmployeeSearchRepository` and asserting the bound `Query`'s BSON shape, independently verified against the real spring-data-mongodb 3.4.12 classpath to correctly fail on pre-patch code and pass only on the fix — but the module would not compile in the isolated worktree (`cannot find symbol: variable log`, `StandardResponse` constructor mismatches in files the diff never touched), so the test never executed and QA gate Status reads Failed (`docs/agent_output/06-test-gate/qa_ISSUE-003.md`). The build gate hit the identical compile failure in the same worktree (`getAddress()`/`getGender()`/`getEmployeeType()` symbols not found, `StandardResponse` constructor mismatches, no dependency drift) and Status reads Failed (`docs/agent_output/06-test-gate/build_ISSUE-003.md`); both failures point to a JDK 25 (build machine) vs. required JDK 17 + Lombok toolchain gap producing missing Lombok-generated symbols in unrelated files, not a defect in the diff's own logic. The merge arbiter scored these five reports per `scoring.json` (`.github/.pipeline-context/merge/ISSUE-003.score.json`): red-team NO_BYPASS_FOUND earns 30/30, behavior BEHAVIOR_CHANGED earns 0/30, QA Failed earns 0/40, for a weighted score of 30/100 against a Critical-severity threshold of 90 — and independently, the build gate's Failed status trips a hard gate that blocks regardless of score. The rendered verdict is Blocked (`docs/agent_output/07-ship/verdict_ISSUE-003.md`), with no override applied since the computed decision was already Blocked and an override can only tighten a computed Cleared decision, never loosen a Blocked one (`.github/.pipeline-context/merge/ISSUE-003.arbitration.json`).
