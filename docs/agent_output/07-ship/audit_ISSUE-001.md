# Audit Trail — ISSUE-001

## Unbounded repository findAll() reads whole collections into memory across multiple services

> ⛔ Blocked — not safe to ship.

_Written by the scribe agent on 2026-08-17, independent of outcome — this file exists whether the patch cleared or was blocked._

## Chain of custody

ISSUE-001 was registered from an architecture review of performance/availability (docs/agent_output/00-issues/issue-register.xlsx) describing three code paths that call MongoRepository.findAll() with no page, limit, or filter, so response cost scales with total collection size. The root-cause report (docs/agent_output/02-root-cause/root_cause_ISSUE-001.md) traced this to EmployeeSchedulerServiceImpl.getAllEmployees() and EmployeeReportServiceImpl.getEmployees(), rated High severity/High confidence because public REST paths (GET /api/v1/employee, GET /api/v1/export) can repeatedly force full-collection materialization. The blast-radius report (docs/agent_output/03-blast-radius/blast_radius_ISSUE-001.md) scoped this to a P1 availability risk affecting sheduler-service and report-service (2 of 10 endpoints, plus the Women's Day scheduled job), with employee-service, discovery-service, department-service and configuaration-server unaffected. The fix strategist's plan (docs/agent_output/04-remediation/fix_plan_ISSUE-001.md, Status: Approved) proposed pushing the bound into the database query itself: server-clamped Pageable pagination for the REST endpoint, a derived findByGender query for the scheduled job, and a paged/streaming rewrite of the export. The Fixer drafted an 8-file diff matching that plan (docs/agent_output/04-remediation/fix_ISSUE-001.md, 'Matches plan: yes') and recorded Status: Compile Failed, with an Open Questions note already identifying the compile failure as a project-wide JDK 25/Lombok annotation-processing gap confirmed by compiling unmodified report-service and employee-service modules off HEAD with no patch applied. Verification then ran three independent checks against the drafted diff: re-scan (docs/agent_output/05-verify/rescan_ISSUE-001.md) found STILL_VULNERABLE at High confidence — the REST endpoint and export path are now correctly bounded, but WomenDaySchedulerImpl.printWomenDayMessage() still calls a Spring Data method (findByGender) that returns a fully materialized, unbounded List<Employee>, matching the CWE-770 catalog's own named anti-pattern of 'fixing the endpoint but leaving an equivalent unbounded call reachable from a scheduled job'; red-team recon (docs/agent_output/05-verify/redteam_ISSUE-001.md) found NO_BYPASS_FOUND — no caller-supplied page/size parameter can force a read back to unbounded, and the one real residual gap is reported under re-scan rather than as a new bypass; behavior guard (docs/agent_output/05-verify/behavior_ISSUE-001.md) found BEHAVIOR_CHANGED (1 out-of-scope change) — a per-record `log.info("employee Salary {}", ...)` line silently disappears as a structural side effect of the rewrite, unmentioned by the fix plan. The QA gate (docs/agent_output/06-test-gate/qa_ISSUE-001.md) and build gate (docs/agent_output/06-test-gate/build_ISSUE-001.md) both report Status: Failed in isolated worktrees, with every compiler error being a missing Lombok-generated getter or the Lombok `log` field on lines the diff either didn't touch or only relocated unchanged from pre-patch code — consistent with the same environment-wide toolchain gap the Fixer's own report already flagged, not a defect this diff introduced. The merge arbiter (docs/agent_output/07-ship/verdict_ISSUE-001.md) computed score 30/100 against an 85-point threshold (High severity), with two independent hard gates triggered — re-scanner STILL_VULNERABLE and build-gatekeeper Failed — either of which blocks regardless of score; no override was applied since the computed decision was already Blocked.
