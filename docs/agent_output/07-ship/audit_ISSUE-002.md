# Audit Trail — ISSUE-002

## Employee PII and payroll data are exposed to unauthenticated callers and written to application logs

> ⛔ Blocked — not safe to ship.

_Written by the scribe agent on 2026-08-17, independent of outcome — this file exists whether the patch cleared or was blocked._

## Chain of custody

ISSUE-002 was registered from a security review of injection/exposure risk (docs/agent_output/00-issues/issue-register.xlsx). The root-cause report (docs/agent_output/02-root-cause/root_cause_ISSUE-002.md, Critical severity) traced this to a complete absence of any Spring Security dependency, filter chain, or method-level authorization in any business service, combined with several handlers logging full sensitive objects/parameters. The blast-radius report (docs/agent_output/03-blast-radius/blast_radius_ISSUE-002.md) rated this P0, with 6 of 10 endpoints across sheduler-service, report-service, employee-service, department-service, discovery-service and configuaration-server named as exposed. The fix strategist's plan (docs/agent_output/04-remediation/fix_plan_ISSUE-002.md, Status: Approved) proposed a deny-by-default SecurityFilterChain (`.anyRequest().authenticated()`, HTTP Basic) added to every named business service, paired with removing the identified sensitive log lines — and the plan's own risk notes already flagged that no identity provider or credential format was defined anywhere, and that securing department-service without adding a service credential to report-service's WebClient call would break that internal call. The Fixer drafted a 12-file diff matching that plan (docs/agent_output/04-remediation/fix_ISSUE-002.md, 'Matches plan: yes') and recorded Status: Compile Failed, with its Open Questions section already identifying the same project-wide JDK 25/Lombok gap confirmed against unmodified report-service off HEAD. Verification then ran three independent checks: re-scan (docs/agent_output/05-verify/rescan_ISSUE-002.md) found FIXED at Medium confidence for the literal reported defect — no service now answers a fully anonymous request, and the flagged log lines are gone — but flagged as a residual indicator that no UserDetailsService/credential store is configured anywhere; red-team recon (docs/agent_output/05-verify/redteam_ISSUE-002.md) turned that residual indicator into a confirmed High-severity BYPASS_FOUND — with no custom user store configured, Spring Boot's auto-configuration falls back to a single default account whose password is printed to that service's own startup logs, giving anyone with log access a fully valid, unrestricted, unaudited credential for every endpoint in that service; behavior guard (docs/agent_output/05-verify/behavior_ISSUE-002.md) found BEHAVIOR_CHANGED with 2 out-of-scope changes — enabling authentication on department-service with no service credential added breaks report-service's GET /api/v1/export flow (a failure mode the plan's own risk notes predicted but the diff still shipped unresolved), and an identical, fully undocumented break exists in employee-service's getEmployeeSalary() call to department-service (mitigated only by an existing circuit breaker giving a graceful 503 rather than an unhandled error). The QA gate (docs/agent_output/06-test-gate/qa_ISSUE-002.md) and build gate (docs/agent_output/06-test-gate/build_ISSUE-002.md) both report Status: Failed across all four services in isolated worktrees, again tracing to missing Lombok-generated getters/builders/log fields on lines the diff itself did not add (confirmed by inspecting the diff's own EmployeeController.java hunk, which only changes log message text, not the surrounding unmodified lines that fail to compile). The merge arbiter (docs/agent_output/07-ship/verdict_ISSUE-002.md) computed score 0/100 against a 90-point threshold (Critical severity) — red-team's confirmed bypass alone caps the maximum possible score at 70 per scoring.json, and behavior/QA both scored 0 as well — with the build gate as an additional, independent hard gate; no override was applied since the computed decision was already Blocked.
