# Step 03 — Development

Implemented changes produced by the **Developer** agent (`03_developer`), one pair per story whose
plan in [`docs/agent_output/02-story-analysis/`](../02-story-analysis/) a human marked **Approved**:

- **`dev_<id>.md`** — the development report: the developer's narrative (what changed, which
  acceptance criteria are addressed), the files touched, and the real build output.
- **`dev_<id>.diff`** — the standalone, directly `git apply`-able patch, captured from a throwaway
  `git worktree` — the Developer never edits the real working tree itself.

## The approval checkpoint

Every plan starts with **Status: Proposed** in `docs/agent_output/02-story-analysis/`. The Developer
will not act on a plan until a human edits that Status cell to **Approved** (or to **Rejected** to
close it out). This is a deliberate pause point between choosing an approach and writing code.

## A Compiled change is not a merge signal

It only means the project builds. Whether the change actually satisfies every acceptance criterion,
survives edge-case review, passes a real test/build gate, and is safe to ship is decided by the rest
of the pipeline — see [`docs/agent_output/06-ship/`](../06-ship/) for the final verdict.

## Reading development Status

- **Compiled** — the diff applied cleanly and the project compiled (and test-compiled) inside an
  isolated `git worktree`.
- **Compile Failed** — the diff was captured but did not compile. The report and diff are still
  published for review; do not apply a change marked this way.
- **Refused** — the Developer would not act because the plan was not `Status: Approved` at the time,
  or no changes were found in the worktree when the change was finalized.
