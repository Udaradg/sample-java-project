# fix(employee-service): parameterize employee search query, remove string-built BasicQuery (CWE-943)

## Summary

- EmployeeSearchRepository.searchEmployees(name, department) no longer builds a MongoDB query by string-concatenating user input into a BasicQuery JSON string.
- Replaced with Spring Data's Criteria/Query API: Criteria.where("name").regex(Pattern.quote(name)), optionally .and("department").is(department) — user input is always bound as a literal value, never parsed as query syntax.
- Closes CWE-943 (Improper Neutralization of Special Elements in Data Query Logic): an attacker can no longer inject MongoDB operators (e.g. $ne, $gt) via the name or department search parameters on the public GET /api/v1/employee/search endpoint.
- Includes a new regression test (mocked MongoTemplate, ArgumentCaptor on the constructed Query) asserting an injection payload produces no operator in the bound query and a benign search still matches correctly.
