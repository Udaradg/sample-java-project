# fix(sheduler-service): cap findAll() reads and push gender filter into MongoDB (CWE-770)

## Summary

- EmployeeSchedulerServiceImpl.getAllEmployees() now calls repository.findAll(PageRequest.of(0, 500)) instead of a bare, unbounded findAll() — response size is capped regardless of collection size.
- Added EmployeeSchedulerRepository.findByGender(GenderType) and service-layer getFemaleEmployees(), so WomenDaySchedulerImpl asks MongoDB for female employees directly instead of loading the entire collection and filtering with a Java stream.
- Scope is intentionally limited to sheduler-service. report-service's EmployeeReportServiceImpl.getEmployees() has the identical unbounded findAll() pattern but needs a streaming fix (it's a full payroll export, not a listing endpoint) — tracked as a separate follow-up, not part of this diff.
- Fixes CWE-770 (Allocation of Resources Without Limits or Throttling): closes an unauthenticated memory-exhaustion primitive on GET /api/v1/employee.
