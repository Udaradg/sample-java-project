## 2. Reasoning

Every signature of the original defect (BasicQuery, StringBuilder, append, and the exact new BasicQuery(<tainted string>) SAST sink) is absent from the patched EmployeeSearchRepository. The two signatures that ARE present (Criteria, Pattern.quote) are not remnants of the old vulnerability -- they are the replacement construction the issue's own Expected Behavior section names as the fix. The mechanism that made this exploitable was that a caller-supplied string was spliced into MongoDB query syntax via string concatenation; the patched code binds 'name' through Criteria.where("name").regex(Pattern.quote(name)) and 'department' through .and("department").is(department), both passing through Spring Data's Criteria/Query API, which serialises values as BSON data rather than parsing them as query-document text. Pattern.quote() specifically neutralises the case that made the original $regex-based injection possible. This closes the injection mechanism itself, not just the reported payload shapes.
