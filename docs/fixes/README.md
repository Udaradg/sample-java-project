# Fixes

Verified patches produced by the **Fixer** agent, one per **Approved** fix plan in
[`docs/fix-plans/`](../fix-plans/). Each entry is a report (`fix_<id>.md`) plus a standalone,
directly `git apply`-able patch (`fix_<id>.diff`) — the Fixer never edits the real working tree
itself.

## Reading Status

- **Verified** — the patch applied cleanly and the affected module compiled (and, if a target test
  was named, passed it) inside an isolated `git worktree`.
- **Verification Failed** — the patch was drafted but did not apply cleanly, or the build/test failed.
  The report and diff are still published for review; do not apply a patch marked this way.
- **Refused** — the Fixer would not act because the linked fix plan was not `Status: Approved` at
  the time. This should not normally appear here — see [`docs/fix-plans/`](../fix-plans/README.md).

"Verified" states the verification *level* recorded in each report (commonly compile-only) — read
the report's Residual risk section before treating a patch as production-ready.
