## 1. What the new test proves

Two assertions against the patched EmployeeSearchRepository.searchEmployees: (1) replaying the exact injection payload from the issue ("x' } }, { 'name': { $ne: '") as the name parameter and capturing the Query passed to MongoTemplate.find, the resulting query document must NOT contain an unescaped $ne operator -- on the pre-patch StringBuilder/BasicQuery code this same payload closes the intended $regex object and injects a $ne clause, so this assertion would fail against the old code and passes against the new Criteria-based construction; (2) a benign search for name=Ann, department=DEP01 still produces a query document containing both literal values, confirming legitimate search behavior is unchanged.

**Mocking strategy:** Mockito-mocks MongoTemplate via @Mock/@InjectMocks (MockitoExtension), capturing the Query argument passed to find(...) with an ArgumentCaptor and inspecting its serialized query document (getQueryObject().toJson()). No @DataMongoTest / live MongoDB is used, since this workspace has no embedded-Mongo dependency and such a test cannot run in this sandbox.
