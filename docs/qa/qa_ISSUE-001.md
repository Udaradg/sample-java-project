## 1. What the new test proves

Two assertions against the patched EmployeeSchedulerServiceImpl: (1) getAllEmployees() calls repository.findAll(PageRequest) rather than the zero-argument findAll() -- on the pre-patch code this test's verify(repository).findAll(pageRequestCaptor.capture()) would fail outright, since there would be no PageRequest argument to capture at all, proving the bound is real and not just asserted; (2) getFemaleEmployees() calls the new findByGender(FEMALE) derived query and never calls findAll() at all, proving the Women's Day job's path no longer loads the full collection before filtering.

**Mocking strategy:** Mockito-mocks EmployeeSchedulerRepository via @Mock/@InjectMocks (MockitoExtension), capturing the PageRequest argument passed to findAll(...) with an ArgumentCaptor and asserting its page size. No @DataMongoTest / live MongoDB is used, since this workspace has no embedded-Mongo dependency and such a test cannot run in this sandbox.
