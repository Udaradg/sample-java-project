# QA Gate — Step 2

Phase C step 2, first half: **qa-runner** drafts one new regression test per fix Fixer drafted a
diff for (mocked, not database-backed — this repo has no embedded-MongoDB dependency) and runs it,
inside an isolated `git worktree`, regardless of whether Fixer's own separate compile check passed
— this gate compiles the module itself, independently. Execution and pass/fail are entirely
deterministic — the agent writes the test, a script decides whether it passed.

## Reading Status

- **Passed** — the new regression test (and any named existing test) ran for real and exited 0.
- **Failed** — something exited non-zero, or the patch/test diff didn't apply. Never overridden.
- **Refused** — the linked fix report's Status was `Refused` (Fixer never drafted a diff at all).

A `SKIPPED` individual test inside a Passed report means this sandbox lacks the dependency that
test needs (commonly a live MongoDB) — it is not counted as a failure, but it is not a pass either.
